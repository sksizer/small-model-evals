## Memory: why in-suite Ollama memory is higher than the perf suite's

The finder showed qwen3.5:9b at 7.9 GB (perf, 8K context, a fresh load) while the fit need said 13.8 GiB (the
sensitive suite). Not the context: the sensitive suite uses 4096 tokens, the perf suite's 32K case reads no
higher than its 4K case (7.3 GiB), and perf's nine text requests do not climb. The cause is how many image
requests one Ollama load has served. In the sensitive suite `/api/ps` `size` rises about 0.12 GiB per request
(qwen3.5:4b) or 0.15 GiB (9b) and levels off after about 70 requests, at +8.0 GiB for both models:

| Model | Perf, 8K, fresh | Sensitive, request 1 | Sensitive, plateau |
| --- | --- | --- | --- |
| qwen3.5:4b | 3.97 GiB | 3.8 | 11.8 |
| qwen3.5:9b | 7.36 | 7.2 | 15.2 |
| lfm3-vl:2b | | 1.6 | 3.2 |

The same +8 GiB for two model sizes rules out weights and KV cache. The two runs of each model (2026-11-04) agree to
0.01 GiB at the same request number, so it follows the request count, not the images. Per-image time does not slow
at the plateau (9b: about 10 s early and late), so this is memory held, not layers pushed to the CPU. The
ledger cannot say whether the runner would release it under pressure; no controlled run was made (the ledger's
two full series already show the ramp, and the harness runs a model only through `scripts/run.ts`, which has no
case filter).

Fix, so the numbers say what they measure (`scripts/fit.ts`, `scripts/export-site.ts`, `site/src/scripts/finder.ts`):
the finder's Memory column reads "7.9 loaded, 8K ctx, fresh" with a second line "15.7 peak in sensitive, 4K ctx"
when the suite peak is at least 5% higher; the Fits need is the in-suite peak (not the median), named with its
context ("measured, sensitive loaded peak at 4K context"). Context lengths come from the suite config and the
provider default, not new record fields, because editing `providers/ollama-sensitive.ts` would have made every
sensitive result stale. Side effect: qwen3.5:4b's need moves from 10.4 GiB to 11.8 GiB (tight, at this machine's
11.84 GiB budget), qwen3.5:9b from 13.8 to 15.2 (offload). Read a high need as "climbs to the budget with images".
